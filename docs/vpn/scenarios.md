# 场景建议：按用途选类型，而不是追“最强”

没有一家服务在所有场景都最好。先明确你主要用在哪里，再选类型和测试重点。

## 场景选择表

| 场景 | 更适合的类型 | 测试重点 | Clash Verge 设置 |
| --- | --- | --- | --- |
| 日常浏览/办公 | Clash 订阅服务 | 晚高峰、常用网站、稳定性 | 系统代理 + 规则 |
| 开发/AI API | Clash 订阅或自建 | 长连接、上传、DNS、额度 | TUN 或环境变量 |
| 视频会议/远程办公 | 稳定订阅/公司合规方案 | 丢包、抖动、UDP | TUN |
| 流媒体 | 有对应地区节点的订阅 | 实际服务、带宽、峰值 | 规则 + 独立组 |
| 游戏/语音 | 支持 UDP 的订阅/自建 | 延迟、丢包、TUN 稳定性 | TUN |
| 旅行/公共 Wi-Fi | 传统隐私 VPN 更合适 | 易用性、跨平台、审计 | 系统级 VPN |
| 多设备/家庭 | 设备数足够的订阅 | 同时在线、限速 | Allow LAN 或逐设备 |
| 高隐私需求 | 审计型 VPN/自建 | 日志、管辖、审计 | 不依赖机场 |

## 1. 日常浏览与办公

**需求**：打开网页、收发邮件、使用 SaaS、看视频。

**建议**：

- 规则模式；
- 系统代理通常够；
- 选一个稳定主节点，不要频繁切换；
- 为常用服务建独立代理组。

**测试**：

- 常用网站是否正常；
- 登录/验证码是否触发风控；
- 晚高峰是否卡顿；
- 公司系统是否禁止代理。

**注意**：有些办公 SaaS 对 IP 地区敏感，频繁切换节点会触发二次验证。固定一个出口更稳。

## 2. 开发与 AI API

**需求**：Git、npm/pip、Docker、API 调用、长连接、上传。

**建议**：

- 优先 TUN，减少“某个工具不读系统代理”的问题；
- 或为终端配置 `HTTP_PROXY` / `HTTPS_PROXY`；
- 选择稳定、低丢包的节点，不要只看延迟；
- 给 API 域名单独建组，固定出口；
- 注意服务商的并发/设备限制。

**测试**：

```bash
# 出口 IP
curl -s https://api.ipify.org

# 长连接/大文件
curl -o /dev/null -w '%{speed_download}\n' \
  'https://speed.cloudflare.com/__down?bytes=100000000'
```

还要测：

- API 是否超时；
- Git clone/push 是否断；
- Docker 构建是否走代理；
- WSL/容器是否能访问宿主机代理端口。

**注意**：AI 服务可能对地区、支付方式、账号风控有额外限制；代理不能保证可用。

## 3. 视频会议与远程办公

**需求**：稳定、低抖动、UDP。

**建议**：

- TUN；
- 选低丢包节点，不只看延迟；
- 避免高峰期限速节点；
- 公司 VPN/零信任客户端优先，不要和 Clash TUN 硬叠。

**测试**：

- 会议 30 分钟以上是否断；
- 共享屏幕/上传是否卡；
- 语音是否断续；
- 切换 Wi-Fi/蜂窝后是否恢复。

**注意**：TUN 与公司 VPN 冲突很常见；先确认组织政策。

## 4. 流媒体

**需求**：特定地区、带宽、稳定。

**建议**：

- 单独代理组；
- 规则按域名分流；
- 选择对应地区节点；
- 不要频繁切换出口。

**测试**：

- 你实际使用的服务能否播放；
- 高峰带宽；
- 是否触发“检测到代理”；
- 多设备同时播放是否限速。

**注意**：服务商的“解锁”宣传不可全信，平台也会持续调整。不要为了流媒体购买长期套餐。

## 5. 游戏与语音

**需求**：UDP、低延迟、低丢包。

**建议**：

- TUN；
- 选游戏专用/低延迟节点；
- 避免链式代理；
- 关闭不必要的规则/脚本；
- 确认反作弊是否允许虚拟网卡。

**测试**：

- 游戏内延迟；
- 丢包/抖动；
- 语音是否断；
- 连续 1 小时是否稳定；
- 关闭 TUN 后网络是否恢复。

**注意**：系统代理不处理 UDP；只开系统代理不能解决游戏问题。

## 6. 旅行与公共 Wi-Fi

**需求**：隐私、易用、跨平台。

**建议**：

- 传统隐私 VPN 通常比机场更合适；
- 选择有公开审计、明确管辖和日志政策的服务；
- 手机/电脑多端支持；
- 公共 Wi-Fi 下优先 HTTPS，VPN 不是万能。

**测试**：

- 酒店/机场 Wi-Fi 是否能连；
- 网络切换后是否自动重连；
- 移动端耗电；
- 是否支持你需要的设备。

**注意**：公共 Wi-Fi 的主要风险是中间人攻击和强制门户；VPN 不能替代 HTTPS 和基本安全习惯。

## 7. 多设备与家庭

**需求**：手机、电脑、平板、电视同时在线。

**建议**：

- 确认设备数/同时连接限制；
- 路由器级代理可以覆盖电视/游戏机，但配置更复杂；
- 或在 Clash Verge 开 Allow LAN，让局域网设备共享；
- 注意限速和隐私边界。

**测试**：

- 同时在线数量；
- 单设备限速；
- 路由器/防火墙是否放行；
- 访客网络是否隔离。

**注意**：Allow LAN 不要暴露到公网；公共网络不要开。

## 8. 高隐私需求

**需求**：尽量避免日志、匿名支付、可审计。

**建议**：

- 传统审计型 VPN 或自建；
- 不使用来源不明的机场；
- 不在代理之外泄露身份；
- 关注管辖、所有权、审计、透明度报告；
- 明白 VPN 不等于匿名。

**注意**：机场通常没有独立审计，不能作为高隐私方案。

## 9. 中国大陆网络环境

需要额外注意：

- 当地法律和政策；
- 服务商的可用性会随网络环境变化；
- 传统 VPN 往往不稳定或不可用；
- 机场跑路/封禁风险高；
- 不要年付/终身；
- 不要在公司/学校网络违反组织政策；
- 不要把订阅链接发到公开群。

**建议**：如果用途是跨境办公，优先使用公司批准的合规方案，而不是个人机场。

## 快速决策

```text
只需要浏览器？
  → 系统代理 + 月付订阅

命令行/开发/AI？
  → TUN 或环境变量 + 稳定节点 + 固定出口

游戏/UDP？
  → TUN + 低丢包节点

隐私/公共 Wi-Fi？
  → 审计型 VPN 或自建，不用机场

多设备/家庭？
  → 设备数 + Allow LAN/路由器方案

高合规要求？
  → 公司批准方案，别用个人机场
```
