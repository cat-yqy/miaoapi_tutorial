# 常见问题与排错

Clash Verge Rev 的问题大多集中在五类：**应用打不开、服务模式失败、TUN 无网、系统代理无效、订阅/规则错误**。

先按这个顺序缩小范围：

1. 关掉代理，直连能不能上网？
2. 代理模式切全局，能不能上网？
3. 系统代理和 TUN 分别试一次，哪个有效？
4. 看“连接”页命中了什么规则，看“日志”报了什么错。

## 一、应用打不开 / 白屏 / 闪退

### Windows：白屏、托盘没反应

Tauri 依赖 WebView2。如果 WebView2 被卸载或禁用：

1. 安装/修复 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)；
2. 或下载带 `fixed_webview2` 的安装包；
3. 检查是否用了第三方工具禁用 Edge/WebView2。

### Windows：闪退或服务装不上

常见原因是安全软件拦截服务安装（360、金山毒霸等）。

- 确认安装包来自官方 Release；
- 暂时退出安全软件，或把 Clash Verge Rev 加入白名单；
- 再重新安装服务；
- 不建议为了装代理长期关闭系统安全防护。

### 架构选错

- 大多数 Windows 是 x64；
- Apple Silicon 选 arm64；
- 旧的 Intel Mac 选 x64；
- 安装错架构可能直接提示“无法在你的电脑上运行”。

### macOS：软件包损坏

官方 FAQ 指出，常见原因是**旧版还在运行时覆盖安装**。

处理：

1. 完全退出旧版；
2. 用卸载工具/手动清理旧版本；
3. 重新安装官方 DMG。

不要在不了解风险的情况下全局关闭 Gatekeeper。

### macOS：被安全软件拦截

公司电脑的安全软件可能禁止安装服务，导致启动失败。需要把 Verge 加入白名单，或联系管理员。

### Linux：Wayland / NVIDIA 问题

常见规避方式（来自官方 FAQ）：

```bash
# NVIDIA + Wayland 部分渲染问题
export WEBKIT_DISABLE_DMABUF_RENDERER=1

# 部分 XWayland 窗口问题
export GDK_BACKEND=x11
```

如果标题栏按钮失效，设置 → 界面设置 → 关闭“优先使用系统标题栏”。

Linux 无图形界面不能运行 Clash Verge Rev；无头环境直接用 Mihomo 内核。

## 二、服务模式失败 / TUN 不可用

### 服务模式是什么

服务模式安装一个特权后台服务，由它拉起内核，从而让普通账户也能用 TUN。服务进程在退出 GUI 后仍可能继续运行，这是正常的。

### Windows：提示“服务内核未通过安全检查，已切换到普通模式（Sidecar）”

这是服务模式的安全检查失败，不是网络问题。

- 应用已退回普通模式，TUN 可能不可用；
- 可以临时“以管理员身份运行” Clash Verge Rev 来使用 TUN；
- 更推荐按官方说明修复安装目录/内核文件的权限，或重新安装到默认目录 `C:\Program Files\Clash Verge`；
- 不要对整个 C 盘递归重置权限或接管所有权，这会破坏系统。

### 服务安装失败

- 确认有管理员权限；
- 检查安全软件拦截；
- 卸载旧服务再重装；
- 查看日志中的具体错误。

### 服务正常但 TUN 还是没网

继续检查：

1. 是否还有别的 VPN/加速器占用虚拟网卡；
2. 防火墙是否放行 `verge-mihomo`；
3. 是否有多余网卡/路由冲突；
4. DNS 是否被改写；
5. 严格路由/自动路由是否与当前网络冲突。

## 三、TUN 模式网络异常

### 打开 TUN 后完全没网

按顺序：

1. 关闭 TUN，确认直连正常；
2. 检查服务模式状态；
3. 关闭其他 VPN、ZeroTier、Tailscale、游戏加速器、Watt Toolkit；
4. 检查 Windows 防火墙/第三方防火墙；
5. 尝试切换 TUN 栈（`gVisor` / `system` / `mixed`）；
6. 临时关闭严格路由，确认是否路由问题；
7. 看日志中的 TUN/route/DNS 错误。

### TUN 和公司 VPN 冲突

两者都可能修改路由和 DNS。不要同时开。

需要公司内网时：

- 用规则把内网域名/IP 直连；
- 用 `nameserver-policy` 指定公司 DNS；
- 必要时分时使用，而不是硬凑在一起。

### 多网卡/多网段冲突

Windows FAQ 提到，系统中多个网卡/网段可能与 TUN 规则冲突。删除不用的虚拟网卡、禁用多余网络适配器后再试。

### macOS 开启 TUN 后 DNS 变了

这是预期行为：TUN 启动时系统 DNS 会临时改为 `223.6.6.6`，由 Mihomo 接管；关闭 TUN 后恢复。

如果关闭后 DNS 仍是旧值，升级到 v2.5.8 或更新版本。

## 四、系统代理无效

### 浏览器可以，命令行不行

系统代理不是全局强制。命令行工具通常不读系统代理。

解决：

- 设置 `HTTP_PROXY` / `HTTPS_PROXY`；
- 用托盘“复制环境变量”；
- 或开 TUN。

### 所有程序都不行

检查：

1. 系统代理开关是否真的打开；
2. 端口 `7897` 是否被占用；
3. 系统代理设置是否被其他软件改回；
4. 系统代理守卫是否和其他代理/VPN 冲突；
5. 是否有安全软件拦截代理设置。

### 端口被占用

```bash
# macOS / Linux
lsof -i :7897

# Windows PowerShell
netstat -ano | findstr :7897
```

换端口，或结束占用端口的程序。

### 部分应用仍不走代理

有些应用不遵守系统代理，例如部分 App Store 应用、游戏、终端工具。

- 在应用内单独设置代理：`127.0.0.1:7897`；
- 或使用 TUN；
- 游戏/UDP 必须用 TUN 或支持 UDP 的方案。

## 五、订阅导入失败

### `client error(Connect)`

官方建议换一种导入方式：

- 订阅链接导入 → 订阅链接配置；
- 或 URL Schemes；
- 检查系统时间、代理、DNS、证书。

### `401`

订阅过期、token 错误、账号被封禁，或订阅链接不完整。

- 重新复制订阅链接；
- 在浏览器里测试；
- 到服务商后台重置订阅。

### `无效的证书`

可能是网络中间人、公司代理、系统时间错误或订阅站证书问题。

只有在明确知道风险时才勾选“允许无效证书（危险）”；不要在公共网络随意关闭证书校验。

### 订阅更新后节点变了

这是正常的。服务商可能调整节点、分组和规则。

- 自定义规则/节点通常独立保存；
- 但扩展配置/脚本可能改变结果；
- 更新后先看“连接”页和“日志”。

## 六、DNS / 内网域名问题

### 内网域名打不开，IP 能打开

给内网域名指定内网 DNS：

```yaml
dns:
  nameserver-policy:
    "+.corp.example.com": "10.0.0.1"
```

如果写在扩展配置里，注意 v2.5.5 起会整体替换订阅的 `nameserver-policy`。需要保留订阅条目时，把它们一起写上，或改用扩展脚本追加。

### 开了 TUN 后部分网站解析异常

- 检查 `fake-ip-filter`；
- 把局域网/特殊域名加入过滤；
- 尝试关闭 fake-ip（不推荐作为默认）；
- 检查 DNS 覆写是否覆盖了订阅 DNS。

### 退出后无法上网

检查系统代理和 DNS 是否残留：

- 手动关闭系统代理；
- 检查系统 DNS 设置；
- 重启网络服务/电脑；
- 升级到修复该问题的版本（v2.5.8 修复了 macOS DNS 残留）。

## 七、规则不生效

1. 看“连接”页实际命中的规则；
2. 自定义规则是否在前置（prepend）；
3. 规则顺序是否被更早的规则截胡；
4. 策略组名称是否写错；
5. `MATCH` 是否在最后；
6. 域名/IP 是否与规则类型匹配；
7. `PROCESS-NAME` 是否有权限拿到进程名；
8. 更新订阅后规则是否被覆盖；
9. Geo 数据是否过期。

调试时切换“全局”验证节点本身，再切回“规则”验证分流。

## 八、性能和日志

### 日志过大

- 日常用 `warning`，不要长期 `debug`；
- 定期清理日志；
- 报问题时只截取相关时间段。

### 节点太多、界面卡

- 减少全量测速频率；
- 拆分代理组；
- 关闭不用的订阅；
- 更新到最新版本（v2.5.8 优化了侧边栏流量图 CPU 占用）。

### GPU 占用高

官方 FAQ 有相关条目。先更新版本；如果仍然异常，检查是否开启了高开销动画/硬件加速相关选项，并附日志反馈。

## 九、如何收集有效信息

报错时至少提供：

1. Clash Verge Rev 版本；
2. 操作系统和架构；
3. 使用的是系统代理还是 TUN；
4. 订阅导入方式；
5. “日志”页相关错误；
6. “连接”页命中规则；
7. 是否安装服务模式；
8. 是否同时运行其他 VPN/加速器。

分享前脱敏：

- 订阅链接/token；
- 节点地址、密码、UUID；
- 本机公网 IP；
- 公司内网域名。

## 十、最后手段：备份后重置

在重装/清配置前：

1. 设置里备份配置，或复制配置目录；
2. 导出日志；
3. 退出应用；
4. 卸载服务；
5. 卸载应用；
6. 重新安装官方版本；
7. 只导入一个订阅，按最小配置测试。

不要一上来就删配置目录；先备份。
