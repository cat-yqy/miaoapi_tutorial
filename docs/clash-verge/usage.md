# 日常使用：托盘、测速、连接与场景

配好之后，Clash Verge Rev 大多数时间在托盘里运行。这一页讲日常操作和常见场景。

## 主界面

左侧通常是：

- **代理（Proxies）**：选节点、测速、看代理组；
- **订阅（Profiles）**：导入/更新配置、编辑规则和节点；
- **连接（Connections）**：实时连接、命中规则、流量；
- **规则（Rules）**：查看当前规则；
- **日志（Logs）**：内核和请求日志；
- **设置（Settings）**：端口、TUN、DNS、启动、WebDAV 等。

顶部常见开关：

- 系统代理；
- TUN 模式；
- 路由模式（规则/全局/直连）。

## 托盘菜单

右键托盘图标可以快速：

- 显示/隐藏主窗口；
- 开关系统代理；
- 开关 TUN；
- 切换规则/全局/直连；
- 切换代理组节点；
- 测试延迟（v2.5.8 新增托盘测速）；
- 复制命令行环境变量；
- 退出。

日常可以完全不打开主窗口，用托盘完成大多数操作。

## 测速与选节点

### 延迟测试

在代理组里点“测试延迟”，会得到每个节点的连接延迟。

注意：

- 延迟低不代表带宽高；
- 测速本身会消耗流量；
- 节点很多时不要频繁全量测速；
- 某些节点可能限制 ICMP/测速 URL，显示超时但实际可用。

### 自动选择

`url-test` 组会按间隔自动选择延迟最低的节点。适合节点多、想省心的场景。

`fallback` 组按顺序故障转移，适合“主节点挂了才切备用”。

`select` 组完全手动，适合需要稳定线路、不想被自动切换的场景。

## 路由模式怎么选

| 模式 | 什么时候用 |
| --- | --- |
| **规则** | 日常默认；国内直连、国外代理、广告拦截 |
| **全局** | 排查“节点本身是否可用”；所有流量走一个节点 |
| **直连** | 排查“基础网络是否正常”；全部不走代理 |

排错顺序：

1. 切直连，确认不开代理能上网；
2. 切全局，确认节点能上网；
3. 切规则，确认分流规则正确。

## 连接页

连接页能看到：

- 源进程/应用；
- 目标域名/IP/端口；
- 命中规则；
- 使用的代理组/节点；
- 上传/下载流量；
- 连接时长。

用途：

- 确认某个网站走了直连还是代理；
- 找出哪个进程在偷跑流量；
- 关闭不需要的长连接；
- 排查规则写错。

有些连接是 UDP/QUIC，系统代理模式下可能看不到或无法代理；TUN 模式下更完整。

## 日志页

日志等级：

- `warning`：日常；
- `info`：排查一般问题；
- `debug`：深入排查，日志量很大。

日志可以复制/导出。提问或报 Issue 时，附上相关日志比“打不开”有用得多。

不要公开包含订阅链接、节点密码、IP 的完整日志。

## 命令行代理

系统代理只影响读取系统设置的程序。命令行工具通常需要环境变量。

Clash Verge Rev 可以复制现成的环境变量：

1. 设置里选择“复制环境变量类型”（PowerShell / Bash / CMD）；
2. 右键托盘 → **复制环境变量**；
3. 在终端执行复制出的命令。

Bash/Zsh 常见形式：

```bash
export HTTP_PROXY="http://127.0.0.1:7897"
export HTTPS_PROXY="http://127.0.0.1:7897"
export ALL_PROXY="socks5://127.0.0.1:7897"
```

如果复制出的 IP 永远是 `127.0.0.1`，可以设置环境变量：

```text
CLASH_VERGE_REV_IP=<你希望使用的 IP>
```

重启应用后再复制。

### Git / npm / pip

很多工具会读取 `HTTP_PROXY` / `HTTPS_PROXY`，但有些需要单独配置：

```bash
# Git
git config --global http.proxy http://127.0.0.1:7897
git config --global https.proxy http://127.0.0.1:7897

# 取消
git config --global --unset http.proxy
git config --global --unset https.proxy
```

npm、pip、Docker 等各有自己的代理配置；不要把系统代理当成“所有工具自动生效”。

### WSL / Docker

WSL 和 Docker 访问宿主机代理时，`127.0.0.1` 可能指向虚拟机/容器自身，而不是宿主机。

常见做法：

- WSL2：使用宿主机在 WSL 网络中的 IP，或在 `.wslconfig` 中配置网络模式；
- Docker Desktop：使用 `host.docker.internal`；
- 确保 Clash Verge Rev 监听地址允许被访问（必要时开 Allow LAN，并限制防火墙）。

不同系统/网络模式差异很大，先确认“容器里能不能访问宿主机的代理端口”。

## 局域网共享

在设置中开启 **允许局域网**，并确认监听地址不是仅 localhost。

其他设备设置：

```text
HTTP 代理：<电脑局域网 IP>:7897
SOCKS 代理：<电脑局域网 IP>:7897
```

注意：

- 防火墙放行端口；
- 只在小范围可信网络使用；
- 不要在公共 Wi-Fi 或公网暴露；
- 最好在路由器/防火墙层限制来源 IP。

## 常见场景

### 1. 浏览器和日常网页

系统代理通常足够。规则模式负责国内直连、国外代理、广告拦截。

### 2. 开发工具和命令行

优先用环境变量或 TUN。

- 只是 Git/npm/pip：环境变量；
- 大量工具、容器、SDK：TUN 更省心；
- 公司内网：给内网域名配置 `nameserver-policy`，并把内网网段设为直连。

### 3. 游戏和 UDP

系统代理不处理 UDP。需要 TUN。

TUN 下要确认：

- 游戏没有反作弊/虚拟网卡限制；
- 没有和游戏加速器冲突；
- 延迟和丢包可接受；
- 规则没有把游戏流量误判为直连/拒绝。

### 4. 多区域/多用途分流

为 AI、流媒体、下载、游戏分别建代理组，然后用规则把域名/进程分配到不同组。

这样可以避免“所有流量挤在一个节点”，也方便单独切换。

### 5. 公司内网 + 外部代理

常见需求：

- 公司内网域名/IP 直连；
- 外部网站走代理；
- 内网 DNS 用公司 DNS。

规则示例：

```yaml
rules:
  - DOMAIN-SUFFIX,corp.example.com,DIRECT
  - IP-CIDR,10.0.0.0/8,DIRECT,no-resolve
  - IP-CIDR,192.168.0.0/16,DIRECT,no-resolve
  - MATCH,PROXY
```

DNS：

```yaml
dns:
  nameserver-policy:
    "+.corp.example.com": "10.0.0.1"
```

### 6. 多份订阅/多台设备

- 多订阅：用 profile 切换，或 `proxy-providers` 合并；
- 多设备：WebDAV 备份配置，或分别导入订阅；
- 不要把包含 token 的配置直接共享给不可信设备。

## 订阅更新与配置切换

- 自动更新按设置间隔执行；
- 手动更新：右键 profile → 更新；
- 更新后节点/规则可能变化；
- 自定义规则/节点编辑通常独立保存，但仍建议备份；
- 切换 profile 会重启内核，短时间断网是正常的。

## 退出与恢复

退出应用时：

- 系统代理应恢复；
- TUN 应关闭，DNS/路由应恢复；
- 如果退出后无法上网，先检查系统代理和 DNS 是否残留。

v2.5.8 修复了 macOS 关闭 TUN/退出后 DNS 残留 `114.114.114.114` 的问题；旧版本遇到类似问题先升级。

## 安全检查清单

- [ ] 订阅链接没有公开
- [ ] 日志分享前已脱敏
- [ ] Allow LAN 只在可信网络开启
- [ ] 公网没有暴露代理/控制端口
- [ ] 公司内网规则和 DNS 已配置
- [ ] 退出后系统代理/DNS 能恢复
- [ ] 重要配置已备份
